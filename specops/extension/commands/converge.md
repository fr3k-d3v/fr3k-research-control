Read the current requirement IDs, task revision, attempt limit and actual Fleet execution receipts. Reconcile the same job's status and complete output first with the FR3K receipt command; do not substitute a claimed result, heartbeat, simulation or stale snapshot. Use the checked-in specops/converge.py planner only with explicit structured inputs. Inputs are assertions until independently authenticated.

Stop on active, blocked, unknown or exhausted attempts. For a demonstrated failure propose a scoped corrective task; for missing or simulated evidence propose collection of actual evidence. Use the stable correction ID and a new attempt ID, retaining prior receipts. All passing input observations lead to REVIEW_REQUIRED, never VERIFIED or release authorization. Output the proposal and acceptance criteria; do not dispatch, approve, cancel, change devices or publish raw private logs. Existing Fleet authority alone decides whether a new job may run.
